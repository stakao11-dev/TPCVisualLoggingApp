お客様には、たとえば次のように説明できます。

## 3. お客様にとってのメリット

### 今でも言えること【提供中】

TPC ロギングと TPC-Excel で、次のことができます（[TPC-Excel 説明書 TB04-1478](../03_reference/tpcexcel/source/TB04-1478-V11.pdf) 2 章より）。

- **特別な測定器が要りません。** コントローラの中で記録するので、現場で手軽に機械の動きを評価できます。
- **機械に負担をかけません。** センサなどを取り付けずに記録できます。
- **ふだん使っている PC と Excel で解析できます。**
- 主な使い道は次のとおりです。
  - サーボ調整の結果を、数字やグラフで判断する
  - メカのガタや、動き出しの引っかかりを調べる
  - 新しい機械の動作確認や、パラメータの調整
  - 動作の異常や精度不良の原因を調べる
  - 出荷前に、実際に加工しなくても精度を確かめる

### 新しいアプリで目指していること【予定】

| 今の困りごと | アプリで目指すこと |
|---|---|
| 記録用のソフトと Excel を使い分け、ファイルを受け渡す手間がかかる | 記録から解析までを、1 つのアプリでできるようにします |
| 結果がグラフだけで、良し悪しの判断が人の経験に頼りがち | 数値でも結果を出し、誰が見ても同じ判断ができるようにします【検討中】 |
| Excel のバージョンによって動かないことがある | Excel が要らない専用アプリにします |
| 位置のデータしか解析できない | 入出力の信号やアラームなど、ほかの記録も使えるようにします【検討中】 |

## 4. 基礎知識

### TPC ロギングとは【提供中】

テクノ製コントローラの中で、機械の動きのデータを **制御と同じタイミング（ずれなし）で記録する機能** です。TPC は「ツールパスチェッカー」の略です。

- 記録できるもの: 各軸の位置（指令した位置と、実際の位置）、入出力信号、アラーム、モーターのトルクなど。RTMC64 では最大 64 種類を同時に記録できます（[RTMC64 送受信データ マニュアル TB00-1044](../03_reference/rtmc64/converted/TB00-1044.md) より）
- 強み: 外から測定器で測るのと違い、コントローラが指令した内容と、機械が実際に動いた結果を、ぴったり同じ時刻で比べられます

### TPC-Excel とは【提供中】

TPC ロギングの記録を解析する、Excel 上で動くツールです。正式名称は「モーションアナライザ TPC-Excel」です。説明書は 2011 年の Ver1.1 です。

使い方は次の流れです。

1. 設定用の PC ソフト（セッティング PC）で記録して、ファイルに保存する
2. そのファイルを TPC-Excel で開いて解析する

### TPCVisualLoggingApp との関係

TPCVisualLoggingApp は **TPC-Excel の後継・進化版** です【予定】。まず TPC-Excel の 3 つの解析（6 章）を引き継ぎ、その後、お客様の声をもとに機能を増やしていきます。

TPC-Excel を今後どう扱うか（並行して提供するか、置き換えるか）は **未定** です。

### 用語集

| 用語 | 意味 |
|---|---|
| TPC ロギング | コントローラの中で、機械の動きを制御と同じタイミングで記録する機能 |
| TPC-Excel | TPC ロギングの記録を解析する Excel のツール（今の解析手段） |
| セッティング PC | コントローラの設定や記録に使う、テクノ標準の PC ソフト |
| 指令位置 / 機械位置 | コントローラが「ここへ動け」と出した位置 / 機械が実際にいた位置 |
| サーボ | モーターを指令どおりに動かす仕組み。「サーボ調整」はその効き具合を合わせる作業 |
| 円弧補間 / 直線補間 | 2 つの軸を同時に動かして、円や斜めの直線を描かせる動き |
| ガタ・ロストモーション | 機械部品のすき間などで、指令どおりに動かない部分 |
| スティックモーション | 動き出しや向きが変わるときの、摩擦による引っかかり |
| タクトタイム（サイクルタイム） | 1 回の作業にかかる時間 |

## 6. できること（予定を含む）

### TPC-Excel から引き継ぐ 3 つの解析

どれも、今の TPC-Excel でできる解析です【提供中】。新しいアプリにも引き継ぐ予定です【予定】。

| 解析 | 何が分かるか |
|---|---|
| サーボ応答精度解析 | 指令に対して、モーターがどれだけ遅れずに付いてきているか、行き過ぎ（オーバーシュート）や速度のムラがないかが分かります。サーボ調整の結果確認に使います |
| 真円精度解析 | 2 軸で円を描かせたとき、きれいな円になっているかが分かります。軸どうしのバランスの悪さや、向きが変わる所の引っかかりを見つけられます |
| 直線精度解析 | 2 軸で斜めの直線を描かせたとき、まっすぐ動いているかが分かります |

新しいアプリでは、次の改良を **検討中** です【検討中】。

- 結果を数値で出す
- 円の中心や基準の直線を自動で求める
- 記録しながらその場でグラフを表示する
- 長い時間の記録を扱えるようにする

最初のリリースにどこまで入れるかは **未定** です。

### 新しい使い道の候補【検討中】

位置と、入出力信号やアラームなどを同じ時間軸で突き合わせると、次のようなことができると考えています。**テクノの仮説で、お客様にとって必要かどうかはまだ確かめていません。** 約束はせず、お客様が同じことで困っていないかを聞く材料に使ってください。

| 候補 | お客様の困りごとの例 |
|---|---|
| センサや出力のタイミングと位置の関係 | センサが反応する位置がばらつく、出力が遅れる |
| 1 サイクルの時間の内訳 | サイクルタイムを短くしたいが、どこで時間がかかっているか分からない |
| アラームが起きる前後の再現 | たまにしか起きない停止の原因が分からない |
| 負荷の変化の監視 | 機械の摩耗や異常に、壊れる前に気づきたい（予防保全） |
| プログラムの進み具合との対応 | プログラムのどこで動きが乱れているか知りたい |

## 8. お客様から聞いてきてほしいこと

このアプリは、**お客様の声を聞いてから機能を決める** 進め方をとります。営業によるヒアリングは、その一番大事な情報源です。

商談や訪問のときに、次の質問をそろえて聞いてください。あとで比べたり数えたりできるよう、なるべく同じ項目で聞きます（質問の項目は企画書の案です【検討中】）。

| 項目 | 聞き方の例 | 答えの例 |
|---|---|---|
| 装置と用途 | 「どんな装置にお使いですか？」 | 加工機、搬送装置、組立装置 |
| 困っていること | 「動きや精度のことで、困っていることはありますか？」 | 精度が出ない、原因の分からない停止がある、サイクルタイムを縮めたい |
| どれくらい起きるか | 「それはどのくらいの頻度で起きますか？」 | 毎日、月に数回、立上げのときだけ |
| 今どう調べているか | 「今はどうやって原因を調べていますか？」 | 測定器を持ち込む、勘と経験、調べられていない |
| 解決すると何が良くなるか | 「それが解決すると、何がどれくらい良くなりますか？」 | 調整の時間、不良の数、停止の時間 |

6 章の「新しい使い道の候補」に近い困りごとが出てきたら、特に詳しく聞いてください。

**聞いた内容の渡し先:** **未整備** です。記録の置き場所と書式（ユースケース台帳・ヒアリング票）、営業の窓口は、まだ決まっていません。決まるまでは、10 章の問い合わせ先に知らせてください。
