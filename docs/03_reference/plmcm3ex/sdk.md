# PLMC-M3EX のソフトウェアパッケージ

PLMC-M3EX のソフトウェアパッケージ（通信ライブラリの本体、ヘッダーファイルなど）は、[sdk/](sdk/) フォルダに置きます。
設計の検討で、構造体や定数の正確な定義を確かめるために使います。

第 1 段階のアプリは RTMC64-EC だけを対象にしています（[ADR-001](../../02_design/decisions/ADR-001_phase1-scope.md)）。
PLMC-M3EX は、設計のときに 3 番目に置く機種です（2026-11-19 Shunsuke、[バックログ B-004](../../02_design/backlog.md)）。2 番目の SLM8000（[slm8000/sdk.md](../slm8000/sdk.md)）と合わせて、インターフェース・構造体・クラスなどを決めるときの判断材料にします。

> **`sdk/` フォルダの中身は Git に入れません。**
> ソフトウェアパッケージとライブラリ本体は、製品を購入した人だけが入手できるものです（[.gitignore](../../../.gitignore) の「製品のソフトウェアパッケージ」）。
> そのため、クローンした直後は `sdk/` フォルダがありません。
> マニュアル（[source/](source/)）は、ホームページでユーザー登録すれば読めるので、Git に入れています。

## クローンしたあとにやること

1. ソフトウェアパッケージを入手します。入手先は **未整備** です（分かる方は追記してください）。
2. `docs/03_reference/plmcm3ex/sdk/` フォルダを作り、パッケージを手を加えずにその下へ置きます。フォルダ名は、パッケージの元の名前（例: `PlmcM3Ex_V240A`）のままにします。
3. `git status` で、パッケージのファイルが表示されないことを確かめます。

| フォルダ | 機種 | 版 | 置いた日 | 備考 |
|---|---|---|---|---|
| `sdk/PlmcM3Ex_V240A/` | PLMC-M3EX | 2.4.0A（通信ライブラリは V220。`Version.sys` による） | 2026-11-19 | 設計で 3 番目に置く機種として調べるため |

DLL のファイルの版は、`Plm3excomnt.dll`（32 ビット版）、`Plm3excomnt64.dll`（64 ビット版）とも 2.2.0.0 です。

## 中身の地図（PlmcM3Ex_V240A）

SLM8000 のパッケージとほぼ同じ構成です。

| 場所 | 中身 | 使い方 |
|---|---|---|
| `devlp/Lib-Com/` | 通信ライブラリ（`Plm3excomnt.dll`、`Plm3excomnt64.dll`）、C/C#/VB/Python 用の宣言 | ★ 設計で一番使う。C# 用は `Plm3excomapiCSNET.cs`（32 ビット）、`Plm3excom64apiCSNET.cs`（64 ビット）、`Plm3exdataCSNET.cs`（構造体と定数）、`Plm3exsyncdefCSNET.cs`（データタイプなどの番号）。接続の設定は `Plm3excomnt.h`。文字コードは Shift_JIS |
| `devlp/pyplm3ex/` | Python 用のラッパーと説明 | TPC ロギングの使い方の手本として読む（`pyplm3ex/McWrapTpc.py`、`McIniParser.py`） |
| `devlp/Ladder/` | ラダーのサンプル（FA-M3R 用） | 読むだけ |
| `devlp/CSNetSmpl/` ほか | C#、VB、C++ のサンプル | 読むだけ。ビルド・実行しない |
| `devlp/Lib-Tcd/`、`Lib-Gcd/` | 運転プログラムの変換ライブラリ | 第 1 段階では使わない |
| 直下の `*.exe`、`flash/`、`Default.rom` | ドライバ、設定ソフト、ファームウェア書き込みなど | **実行しない**。コントローラの状態を変えるおそれがある |
| `Version.sys` | 版の一覧 | 版を確かめるときに読む。社内のファイルサーバーのパスが書かれているので、中身を Git に入るファイルに写さない |

## TPC ロギングについて分かったこと（2026-11-19）

マニュアル（TB00-0984 送受信データ）とパッケージ 2.4.0A を照らし合わせて分かったことです。マニュアルはまだ Markdown にしていないので、PDF の文字を読んで照合しました。

| 項目 | 分かったこと | 根拠 |
|---|---|---|
| コマンドの並び | 設定（`REQ_TPCSEL_EX` 0x3E）→ 開始（`REQ_TPCLOG` 0x32）→ 状態（`DAT_TPCINFO_EX` 0x2A）とデータ（`DAT_TPCDATA` 0x25）の読み出し。RTMC64-EC、SLM8000 と同じ | TB00-0984 4-1-15、4-1-23、4-2-51、4-2-55、`Plm3exsyncdefCSNET.cs` |
| **64ch ロギングがない** | ロギング種別は「ポジション・入出力（2ch）」と「MECHATROLINK 通信」だけ。64ch の設定の構造体（`TPCSEL_64CH`）も、64ch のデータを読むデータタイプもない | `Plm3exdataCSNET.cs` の `TPCH_LOG_*`、`TPCSEL_*` |
| ロギング種別の値 | パッケージでは 0: ポジション・入出力、1: MECHATROLINK 通信（`TPCH_LOG_ML`。32 バイトか 48 バイトの通信データを、送受信・送信のみ・受信のみで記録する）。マニュアル（TB00-0984 4-2-55）は「0固定」で、1 の記載がない。1 は使えるが、ユーザーに公開していないデバッグ用の機能として存在している（2026-11-19 Shunsuke 確認）。顧客に提供するアプリで扱うかは、別に決める必要がある | `Plm3exdataCSNET.cs` の `TPCH_LOG_*`、`TPCSEL_ML`、TB00-0984 4-2-55 |
| 2ch で選べる位置 | 第1・第2ポジション番号はそれぞれ 0～17（第1～第9軸の指令位置と機械位置）。**仮想指令位置は選べない** | TB00-0984 4-2-41 |
| データ 1 点の大きさ | 2ch は 16 バイト（`TPCDAT_POS`: 位置 4 バイト + 汎用入力 2 バイト + 汎用出力 2 バイト、を 2 組） | TB00-0984 4-1-15、`Plm3exdataCSNET.cs` |
| バッファ | 最大 65,536 バイト。読み出すとその分が空き、読み出しが間に合わずに一杯になるとロギングが止まる | TB00-0984 4-1-15、4-1-23 |
| ロギング周期の単位 | **msec**（0～32767）。構造体のコメントと一致。Python のラッパーの説明「制御周期間隔」は誤り（2026-11-19 Shunsuke 確認） | TB00-0984 4-2-55、`McWrapTpc.py` の `TpcDataPos.__init__` |
| 制御周期の読み出し | データタイプの名前が `DAT_CYCLE`（0x91、「サイクリック周期情報」）で、RTMC64-EC・SLM8000 の `DAT_CYCLETIME` と名前が違う。構造体 `CYCLETIME` の中身は SLM8000 と同じ `CycleTimeMax`、`CycleTimeNow`（単位のコメントなし）。マニュアルには載っていない。アプリが使う制御周期は、SLM8000 と同じく ini ファイルから取得する（2026-11-19 Shunsuke 確認。下の行） | `Plm3exsyncdefCSNET.cs`、`Plm3exdataCSNET.cs` |
| 制御周期の取得 | SLM8000 と同じく、ドライバの設定ファイル `plm3exdrv.ini` から取得する（2026-11-19 Shunsuke 確認）。Python のラッパーは `[Program]` の `RTCTime`（制御サンプリング周期、μsec）として読んでいる | `pyplm3ex/McIniParser.py`、`example/*.py` |

## 通信設定ファイル（plm3exdrv.ini）

RTMC64-EC の `rt64ecdrv.ini`、SLM8000 の `slm8000drv.ini` と同じ設計のファイルで、コントローラとの通信設定が書かれています（2026-11-19 Shunsuke 確認）。セッティング PC などと同じファイルを参照すれば、同じコントローラにつなげます。
セクションは `[Communication]`、`[Program]`、`[Task0]`～`[Task7]`、`[I/O Port]`、`[Option]` です。通信設定には、パソコンリンクの IP アドレス（`PcLnkIpAddr`）などがあります（`pyplm3ex/McIniParser.py`）。

## RTMC64-EC、SLM8000 との違い（設計で気をつけること）

| 項目 | RTMC64-EC | SLM8000 | PLMC-M3EX |
|---|---|---|---|
| 64ch ロギング | あり（種別 2） | あり（種別 1） | **なし** |
| 記録できる位置の組み合わせ | 64ch で自由に選べる（第 1 段階は 2 軸 × 3 種類 = 6ch） | 同左 | **2ch だけ**（指令位置か機械位置を 2 つ）。仮想指令位置は選べない |
| 制御周期の読み出しのデータタイプ | `DAT_CYCLETIME`（`CycleTime`） | `DAT_CYCLETIME`（`CycleTimeMax`、`CycleTimeNow`） | `DAT_CYCLE`（`CycleTimeMax`、`CycleTimeNow`） |
| 制御周期の設定値の読み方 | `DAT_CYCLETIME` | `slm8000drv.ini` の `RTCTime` | `plm3exdrv.ini` の `RTCTime` |
| つなぎ方 | 同じ PC の中で共有メモリ | イーサネットか RS-232C で別の基板へ | 横河電機の PLC「FA-M3R」のパソコンリンク（イーサネットか RS-232C）を経由。接続の設定（構造体 `SXDEF`）で、CPU 番号、ユニット番号、スロット番号、ステーション番号、IP アドレスとポートなどを指定する |
| 物理軸・論理軸 | 64 / 9 | 8 / 9 | 9（2ch のポジション番号は第1～第9軸） |
| 通信ライブラリの DLL | `Rt64eccomnt(64).dll` | `slm8000comnt(64).dll` | `Plm3excomnt(64).dll` |

設計への影響: 機種によって、記録できるチャンネルの数と、選べる位置の種類が違います。取得部品は「この機種で何が記録できるか」を持ち、画面や解析はそれに合わせて、選べる組み合わせを変える必要があります（たとえば PLMC-M3EX では、3 種類の位置の比較はできず、TPC-Excel と同じ 2 列だけになる）。

## 注意

- パッケージの中身は書き換えません。Claude Code は、権限設定で `sdk/` の下の書き換えを拒否されています（[.claude/README.md](../../../.claude/README.md)）。
- パッケージに入っているプログラム（サンプル、ドライバ、設定ソフト、ファームウェア書き込みなど）は、ビルドも実行もしません。軸を動かしたり、コントローラの状態を変えたりするおそれがあるためです（[constitution](../../../.specify/memory/constitution.md) 原則 I）。
- ヘッダーなどの中身を、Git に入るファイルにそのまま写さないでください。設計に必要な点は、この資料のように、要点と、どのファイルにあるかを書くにとどめます。
