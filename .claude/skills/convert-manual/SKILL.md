# PDF マニュアルの Markdown 変換

`docs/03_reference/<製品>/source/` にある PDF マニュアルを、後から AI や人が読める Markdown にする。
機械的な変換は [scripts/convert_pdf.py](../../../scripts/convert_pdf.py) が行う。この skill では、スクリプトにできない **図の書き起こし** と **崩れた表の修正** を Claude が行い、変換を仕上げる。

## 守ること

- **出力された `.md` は直接編集しない。** 変換のたびに作り直されて、手で直した内容は消える。直したい内容は必ず `figures.yaml` / `tables.yaml` に書く
- 原本（`source/` の下）は書き換えない（settings.json でも禁止している）
- 推測で書かない。図や表から読み取れないことは書かず、判読できない箇所は「（判読できず）」と書いてユーザーに報告する
- `convert_pdf.py` 自体の変更（後処理の不具合の修正など）は、ユーザーに頼まれたときだけ行う
- コミットはユーザーに頼まれたときだけ行う

## 出力先

PDF が `docs/03_reference/<製品>/source/<名前>.pdf` にあるとき（`source/` の下のサブフォルダにあっても同じ）:

```
docs/03_reference/<製品>/converted/
    <名前>.md            変換結果（スクリプトが作る）
    <名前>/
        images/          図の PNG（スクリプトが変換のたびに作り直す）
        figures.yaml     図の書き起こし（この skill で書く）
        tables.yaml      表の手修正（この skill で書く）
```

既存の例: `docs/03_reference/rtmc64/converted/TB00-1044/` の figures.yaml と tables.yaml。書き方に迷ったらこれに合わせる。

## 手順

### 0. 対象を決める

- 引数で PDF が渡されたら、それを対象にする
- 引数がなければ、`docs/03_reference/*/source/` にある PDF のうち `converted/` に `.md` がないものを一覧にして、どれを変換するかユーザーに聞く
- 既に `.md` がある PDF は「作り直し」として扱い、既存の figures.yaml / tables.yaml を読んでから進める（書いてある内容は消さない）

### 1. 変換する

```
.venv/Scripts/python scripts/convert_pdf.py <pdf>
```

- このコマンドは確認なしで実行できる（settings.json で許可済み）。PowerShell では `.\.venv\Scripts\python scripts\convert_pdf.py <pdf>` でもよい
- 初回は docling の解析に数分〜十数分かかる。時間がかかるのでバックグラウンドで実行し、終わるのを待つ。2 回目以降は `.cache/docling/` のキャッシュを使うので速い
- 解析からやり直すのは `--reconvert` を付けたとき。PDF を差し替えたとき以外は付けない
- `.venv` がない、または `ModuleNotFoundError` が出たら、作業を止めてユーザーに伝える。必要なパッケージは `docling pypdfium2 PyYAML`（`pip install` は毎回確認が出る設定になっている）

実行結果の次の行を控えておく:

- `figures without description (N): <ハッシュ>, ...` — 書き起こしがない図
- `table fix anchor not found` / `table not found after` — tables.yaml の `after` が見つからない

### 2. 図を書き起こす（figures.yaml）

画像だけでは後から読む AI が内容を理解できないため、図の内容を文章にする。

1. 書き起こしがない図のハッシュごとに、`images/` の中で名前にそのハッシュを含む PNG を Read で見る
2. `.md` の中でその画像がある位置の前後を読み、どの章の何の図かを確かめる
3. 画像だけで細部（小さい文字、ビット番号、矢印の向き）が読めないときは、PDF の該当ページを Read（`pages` 指定）で見る。それでも分からなければ、画素を調べる使い捨てのスクリプトを scratchpad に書いて確かめてもよい（例: ビット図の引き出し線の位置からビット番号を求める）
4. `figures.yaml` に書く

```yaml
# <名前> の図の書き起こし
# scripts/convert_pdf.py が変換時に、各図の直下へ「図の内容」として差し込む。
# キー: 画像ファイル名 (image_NNNNNN_<hash>.png) のハッシュ値の先頭 8 桁

0fde5fc4:
  alt: 図の短い題名（本文の図番号や見出しに合わせる）
  text: |
    図の内容を Markdown で書く。
    - 箇条書き、表、コード（`DAT_xxx` など）を使ってよい
```

書き方:

- キーはハッシュ値の **先頭 8 桁**。ファイルの並びは `.md` に出てくる順にする
- `alt` は必ず書く。`text` は、ロゴや飾りなど内容のない図では省略する
- 図に書かれた **文字・数値・名前はそのまま写す**（全角・半角、記号も PDF のとおり）。要約して数値を丸めない
- 構成図・フロー図は「何が、何と、どうつながるか」を、ビット図・メモリ配置図は全てのビット・オフセットを表や箇条書きにする
- 読み方に注意が要る点（改訂マーク、LSB=D0 など）は `text` か、ファイル冒頭のコメントに書く
- 図が多いとき（数十枚以上）は、章ごとなど区切りのよいところで一度ユーザーに進み具合を伝える

### 3. 崩れた表を直す（tables.yaml）

docling は結合セルのある表を読み違えやすい。`.md` の表を全て見て、次のような表を探す:

- 行によって列の数が違う、空のセルが不自然に多い
- 1 つのセルに複数の値が詰め込まれている、値が隣の列や次の行にずれている
- 見出し行が本文の行として扱われている、1 つの表が 2 つに分かれている

見つけた表は、PDF の該当ページを Read で見て照合し、`tables.yaml` に正しい表を書く。

```yaml
# <名前> の表の手修正
# 結合セルなどで docling が正しく読めなかった表を、PDF と照合して書き直したもの。
# scripts/convert_pdf.py が変換時に、after を含む行の後ろにある最初の表をこの内容に差し替える。

# <章番号と題名>: <表の内容> (PDF <ページ> ページ)
# <何が崩れていたか>
- after: 表の直前にある本文の一部
  table: |
    | 見出し | ... |
    |---|---|
    | ... | ... |
```

- `after` は `.md` の中で **一意に決まる** 文字列にする（同じ文が別の章にもあると、最初に見つかった方の表が差し替わる）。表の直前の文で一意にならなければ、もっと前の見出しなどを使う
- 結合セルは、結合されていた値を各行に繰り返して書く（Markdown の表は結合を表せないため）
- 各項目の上のコメントに、章・PDF のページ・何が崩れていたかを書く

### 4. 変換し直して確かめる

もう一度 `convert_pdf.py` を実行する（キャッシュを使うので速い）。

- `figures without description`、`table fix anchor not found`、`table not found after` が出なくなるまで 2〜3 を繰り返す
- `.md` を見て、図の直下に「図の内容」が入っていること、差し替えた表が正しい位置にあることを確かめる
- あわせて、スクリプトの後処理で直しきれていない箇所（コードブロックの崩れ、見出しの抜け、目次の崩れなど）がないか、ざっと目を通す。見つけたら **`.md` は直さず**、場所と内容を控えて報告する

### 5. 終わったら

ユーザーに次を報告する:

- 変換した PDF と出力先、図の数（書き起こした数／text を省略した数）、直した表の数
- 判読できなかった箇所、自信がない書き起こし（人に確認してほしいもの）
- スクリプトで直すべき崩れ（`.md` には手を入れていない）
- 新しい製品のマニュアルを初めて変換した場合は、オンボーディング資料（`docs/00_onboarding/onboarding_dev.md` の「Markdown 版はまだありません」など）が古くなるので、`/onboarding-dev` での更新を提案する
